1. What Figma's player does with a spring (viewer bundle)
---------------------------------------------------------
- s1.easingFunctionValues(): for CUSTOM_CUBIC, GENTLE_SPRING, SPRING_PRESET_ONE/TWO/THREE and CUSTOM_SPRING the
  action's own easingFunction when it has one, else the preset's numbers (legacy SPRING and the beziers: the preset).
- s1.transitionDuration(): the stored transitionDuration (≥ 0), else 0.3.
- s$.getYValueForXValue(x) = spring.solve(x · durationSeconds): the physical spring runs in real seconds over the
  stored duration.
- sX (the spring): ω₀ = √(k/m), ζ = c / (2√(km)); ζ < 1 the under-damped closed form; ζ ≥ 1 the critically damped
  curve at ω₀: 1 − (1 + (ω₀ − v₀)t)·e^(−ω₀t) (Slow, ζ ≈ 1.118, plays as critical).
So the owner's card hover lasts 0.417 s and moves 1 − (1 + 26.8t)e^(−26.8t); a Push 0.625 s.

Wecra before: `proto::durationOf` ignored the stored duration for every spring and played the preset's own settle
time, and `springOf` ignored easingFunction for presets — every Slow animation of the file ran Slow's own 1.25 s:
3× (cards), 4.8× (buttons) and 2× (navigation) longer than Figma, with the over-damped curve (slower start). That is
the "very heavy" playback: frame pacing was never the problem (below).

6. Hug anchors — where an instance goes when a variant switch changes its size (2026-10-20, later)
--------------------------------------------------------------------------------------------------
The owner's recording: "Frame 5" (523 × 349) with an instance of "Buttons" (secondary / xl, Hug × Hug, 196 × 52 at
163, 148.5, constraints Center / Center), Mouse enter → Change to the hover variant (another size), Smart animate,
Slow. Figma grows / shrinks it around its centre; Wecra kept its top-left and grew it right and down.

How: live Figma, the owner's file, a scratch page "zz anchor test" made for it (deleted afterwards). A set "AnchorBtn"
of two Hug variants (a 100 × 40 box, a 200 × 80 box), instances at (150, 130) in 400 × 300 frames with each
constraint pair; plugin API setProperties (the panel's variant switch) and the presentation (Mouse enter → Change to,
Smart animate, Linear 3 s; the page's clock held by script — performance.now and the animation frames' time replaced —
so a transition is shot at exact times; the same trick in Wecra, scripts/proto-bench/frames.mjs).

Variant switch in the editor (setProperties), the instance (150, 130, 100 × 40) → 200 × 80:
  Left / Top                     (150, 130)   the top-left stays
  Right / Bottom                 ( 50,  90)   the right and bottom edges stay
  Center / Center                (100, 110)   the centre stays
  Left & Right / Top & Bottom    (100, 110)   the centre stays (the instance takes the variant's size, not stretched)
  Scale / Scale                  (100, 110)   the centre stays
  Center / Top                   (100, 130)   per axis
  in a vertical auto-layout frame centring it: placed by the frame (100, 110)
  in a Hug row [50 · instance · 50]: the row re-lays out (the instance at x 60, the row grows)
Not specific to instances — any Hug auto-layout frame whose content grows (a child rectangle 100 × 40 → 200 × 80):
  Center / Center (20, 20) → (−30, 0); Right / Bottom-ish (MAX / MIN) (100, 100) → (0, 100); MIN / MAX → (100, 60);
  STRETCH / SCALE → (50, 80). On the canvas (no parent frame): the top-left stays.
Not like that:
  - fixed-size variants (no Hug): the top-left stays whatever the constraints (Center, Right, Stretch: all at (150, 130));
  - an auto-width text: grows from the side its text alignment holds, constraints ignored (MAX + Left aligned grew right);
  - a custom instance name stays across variant switches ("My custom" kept; Wecra now keeps it too).
Prototype: Change to with Smart animate interpolates position and size together — the centre held on every frame
(Center: the box's centre at the frame's centre at 1 s, 1.5 s, 2 s of 3 s; Right / Bottom: the right / bottom edges
held). Instant: the end state above. In an auto-layout parent the parent re-lays out every frame: the row's siblings
move and the Hug row grows continuously (a 50 · 100→200 · 50 row: half way the right square half way along), not at
once.

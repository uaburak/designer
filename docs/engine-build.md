# Engine: build, run, test, API (milestones E0 + E1 + E2 + E3 + E4 + E5, E6 components, E6 variables + styles, E6 libraries; Figma parity rounds 3–4; import fidelity; E7 export; E8 prototyping)

## Round 5 — variables and components (2026-10-08, branch `r5-variables-components`)

Figma's variable features that were "kept as data, not applied" (E6 variables "Not done") and the component panel's gaps. Research: docs/research/figma/R3-variables.md "Round 5 additions"; the encodings were read from the owner's private file (nothing derived from it committed).

**Schema** (`schema/document.kiwi`, docs/schema.md §6.2, §6.3, §6.6): `VariableDataType.MAP` / `VariableResolvedDataType.MAP`, `VariableAnyValue.mapValue` (`VariableMap {values: [VariableMapValue {key, value, guidKey}]}`), `NodeType.VARIABLE_OVERRIDE`, `VariableSetMode.parentVariableSetId` / `parentModeId`, `VariableModeBySetMapEntry.variableSetExtensionID`, `NodeChange.overriddenVariableId` (464). The .fig import now keeps Figma's RESOLVE_VARIANT bindings (their MAP argument was dropped before).

**Engine model**: `VariableData::Kind::MAP` (`args` = values, `mapKeys` / `mapGuidKeys`); `VariableSetMode::parentSet` / `parentMode`; `VariableModeEntry::extension`; `AssetFacet::overriddenVariableId` (`F_OVERRIDDEN_VARIABLE`, bit 114); `ComponentPropDef::boundValue` / `ComponentPropAssignment::boundValue` (their `varValue` when it is an alias; any other `varValue` stays raw bytes in `extra`, written back unless a binding replaces it). Constructors `VariableData::isTruthy`, `VariableData::resolveVariant`.

**Resolution** (`editor/Variables.cpp`):
- Expressions in bindings: `IS_TRUTHY` (how Figma's files bind every boolean to visibility — the 125 such bindings in the owner's file were not applied before), `NOT`, `AND`, `OR`, `EQUALS`, `NOT_EQUAL`, comparisons, `ADDITION` (numbers, or string concatenation), `SUBTRACTION`, `MULTIPLY`, `DIVIDE`, `NEGATE`, `STRINGIFY`, `TERNARY`; `COMPOSE_COLOR` as before.
- **Variable-driven variants** (`variantFor`): `VARIANT_PROPERTIES` = RESOLVE_VARIANT(MAP {property → alias}). A real instance writes the variant it resolves to into `symbolData.symbolID` (its changes remapped as a variant switch), in the same transaction (a mode switch, a value edit, undo); a nested instance chooses its variant while its instance is derived, in the derived row's own modes (`ModeContext::pending`: rows being built answer for their parents). The variant: every bound property equal to its variable's value (numbers as text, booleans `true` / `false`; case-insensitive when nothing matches exactly), the most other values kept; none: unchanged.
- **Bound property values** (`applyBindings`' resolver): a default (`ComponentPropDef.boundValue`) or an assignment (`boundValue`) resolves in the level's modes; an instance whose derivation read variables is re-derived when they change (`instanceVarDeps_`, its expansion's deps merged into its own).
- **Extended collections**: `modeFor(ctx, set, &extension)` honours an entry naming an extension of `set` (one mode value per collection); `valueInMode` walks extension → parent → … → the variable's own value. Overrides are indexed (`overridesBySet_`, `overrideIndex_`, rebuilt at load, kept by `noteBindings`); a change to one re-resolves what read its collection. `syncExtensions` (start of `flushBindings`) keeps local extensions' modes in step with their parent's (names, order, new modes; orphans kept) — after commands, undo, remote changes and library updates alike.
- **Grid gaps**: `GRID_ROW_GAP` / `GRID_COLUMN_GAP` write `gridRowGap` / `gridColumnGap` (kiwi bytes in `NodeProps::extra`, what `layout/GridLayout.cpp` reads); detached when edited.
- **A nested instance's own slot content inside a main** (`expandChildren`): the content frame under the nested instance in the main is expanded into the slot's derived rows of every instance of that main (row ids under the slot row, override paths with the slot's prefix); edits to it re-derive them.

**Commands** (`abi.ts CommandId`):
- `EXTEND_VARIABLE_COLLECTION` 168 `{collection, name?}` — "Extend collection": a VARIABLE_SET with one mode per parent mode (same names, fresh ids, `parentSet` / `parentMode`), right after the parent; default name "<parent> extended" (Figma's default is unverified). Library copies may be extended (a local extension of a subscribed collection).
- `RESET_VARIABLE_OVERRIDE` 169 `{collection, variable | variables, mode?}` — "Reset change": removes the extension's value for that mode (no mode: every mode); an override left empty is removed.
- `SET_VARIABLE_VALUE` with a mode of an extended collection writes its override (creating the VARIABLE_OVERRIDE); refused on a library copy's extension.
- `SET_VARIABLE_MODE {collection: <extended collection>, mode}` writes the root collection's entry naming the extension.
- `BIND_VARIABLE` targets `componentProperties.<name>`: on an INSTANCE (real or derived) a VARIANT property ("Assign variable"; STRING / FLOAT / BOOLEAN variables; one RESOLVE_VARIANT entry holding every bound property; `variable` null removes one); on a main / set a BOOL (BOOLEAN variable) or TEXT (STRING variable) default ("Apply variable"). A VISIBLE binding is written as `IS_TRUTHY(alias)`.
- `SET_COMPONENT_PROPERTY` of a VARIANT detaches that property's variable (an edit of a bound value).
- Refused on extended collections: `CREATE_VARIABLE`, every mode command, `DUPLICATE_VARIABLE_COLLECTION`. `DELETE_VARIABLE_COLLECTION` takes the collection's extensions (and theirs) and their overrides; a hard-deleted variable's overrides go with it.

**Reads**: `variableCollections()` adds `isExtension`, `parentCollectionId`, `rootCollectionId`, `modes[].parentModeId`; an extension's `variableIds` are its root's. `variables(extension)` lists the root's variables. `VariableInfo.valuesByMode` / `resolvedValuesByMode` add every extension's modes (override or inherited value) and `overriddenModes`. `variableModes(ref)` reports an extension's explicit / resolved mode under the extension's id. `boundVariables` lists a variant binding as `componentProperties.<name>` per property, and bound defaults / values likewise. `componentInfo` properties add `boundVariable`. `Editor::extensionParent`, `rootCollection`, `overrideNode`, `extensionsOf`, `collectionOfMode`, `explicitModeOf`, `valueForMode`.

**Libraries**: an extended collection is an asset like any collection; its payload's closure takes its parent (`parentVariableSetId` is a reference) and the variables its overrides name (`overriddenVariableId`); the overrides travel as its children (in its versionHash). Imported copies resolve; updates rewrite them; a consumer can extend a library collection and override its copy's values locally (the read-only guard lets `EXTEND_VARIABLE_COLLECTION`, and `SET_VARIABLE_VALUE` / `RESET_VARIABLE_OVERRIDE` into a local extension, through).

**Not applied, on purpose**: Timing / Easing variables in prototypes — Figma doesn't bind transition duration / easing to variables (feature requests open as of 2026; they drive Motion presets, which this app doesn't have). `HYPERLINK`, `FONT_VARIATIONS` and per-run text bindings stay data.

**Tests**: `engine/tests/unit/variables.extended.test.cpp` (9 cases: IS_TRUTHY, expressions, a bound variant and its undo / detach, a nested bound variant per instance modes and at the usage site, extended collections end to end incl. kiwi round trip and delete, a bound boolean default, grid gaps, nested slot content, the codecs), `libraries.test.cpp` "libraries (r5)" (publish an extension with its parent, consume, update, extend the copy locally). `npm run engine:test` 315 cases green. Release wasm 3464 KB.

## E8 prototyping — API and status (2026-10-08)

Figma's prototyping (docs/research/figma/R8-prototyping.md): the engine draws prototype mode's marks on the canvas, edits connections by dragging, and plays prototypes (the presentation view) with the same renderer. Branch `e8-prototype`.

**Data: the schema's fields, unmodelled in NodeProps.** `prototypeInteractions`, `prototypeStartingPoint`, `prototypeDevice`, `prototypeBackgroundColor`, `overlayPositionType`, `overlayRelativePosition`, `overlayBackgroundInteraction`, `overlayBackgroundAppearance`, `scrollDirection`, `scrollBehavior` stay kiwi bytes in `NodeProps::extra` (they round-trip with `.fig` files, saves, copies and undo untouched; no NodeProps field was added). `engine/src/proto/Prototype.{h,cpp}` reads them on demand (through the schema's JSON view of the bytes, `codec::extraValueToJson`) into `proto::Interaction` / `Action` / `OverlaySettings` / `Device` / `Flow`, writes them back (`encodeInteractions`, `encodeField`), and has the easings (Figma's cubic-béziers: Ease in (0.42, 0, 1, 1), Ease out (0, 0, 0.58, 1), Ease in and out (0.42, 0, 0.58, 1), the back curves; springs as damped oscillators — Gentle 1/100/15, Quick 1/300/20, Bouncy 1/600/15, Slow 1/80/20, custom from `easingFunction` — with their settle time as duration). Instances inherit their main's interactions (an INSTANCE without its own `prototypeInteractions` reads its main's: `kNotInherited` keeps `extra` off the materialized root). Panels read and write the fields as JSON through `engine_read_nodes` / `engine_set_props` like any unmodelled field (enums by name, GUIDs `{sessionID, localID}` or "s:l"); `engine_read_nodes` with `fields` now also returns unmodelled fields named in the list (it adds `extra`).

**Prototype mode** (`editor/PrototypeEditing.cpp`, `render/PrototypeOverlay.cpp`):
- `engine_set_prototype_mode(h, on)` (`Engine.setPrototypeMode(on)`; the editor sets it with the Prototype tab).
- The overlay (`Overlay::prototype`): every connection on the page — hotspot → destination for each Navigate / Open overlay / Swap overlay / Change to / Scroll to action, conditional branches included — as a 2 px blue cubic leaving the hotspot's side facing the destination with a dot, ending at the destination's facing side (level with the hotspot where it can) in an arrowhead (`prototypeNoodle()` is the shared geometry); the selection's connections bright, the others at 35 % when something is selected. The selected layers show the connection handle on their right edge (a blue dot; hovered, a white circle with a blue plus). Frames with a flow starting point get Figma's blue label (play icon + the flow's name) where the frame title starts; the title moves right past it.
- Gestures (hooks in `tools/Gestures.cpp`, `Gesture::Noodle`): a press on a handle drags a new noodle (from every selected hotspot); over a top-level frame it outlines it; released there, each hotspot gets **On click → Navigate to that frame, Instant (300 ms Ease out kept for when an animation is picked)** — one undo step "Add interaction" — and, when no flow reaches the source's top-level frame yet, that frame gets a flow starting point "Flow N". A press on a selected connection's arrow drags its end: dropped on another frame it retargets the action, on empty canvas it removes it (the interaction with it when it was its only action). The JSON is edited in place, so fields the engine doesn't read survive. Event **`PROTOTYPE_CONNECTED {refs, interaction}`** (the panel opens that interaction's details).

**The player** (`proto/Player.{h,cpp}`; `engine_present_*`). The presentation view runs on an engine of its own (its own tab or the overlay in the editor), which loads the file and then presents:
- `engine_present_start(h, pageSess, pageLocal, nodeSess, nodeLocal)` — `0xffffffff` pairs: the current page, then the first flow's start (flows ordered by `prototypeStartingPoint.position`), else the first frame (left to right, then top to bottom). The content cache is off while presenting; `engine_present_stop(h)` puts the canvas back.
- Input: `engine_present_pointer(h, type, x, y, buttons, mods)`, `engine_present_wheel(h, x, y, dx, dy, deltaMode)`, `engine_present_key(h, 0 down | 1 up, jsKeyCode, mods)` (the prototype's Key/Gamepad triggers first — Figma's keyCodes, modifiers as 16/17/18/91 —, then R restart, → / Space / N next frame, ← previous, Z scale). While presenting, `engine_pointer` / `engine_wheel` go to the player too.
- `engine_present_command(h, 0 restart | 1 next | 2 previous | 3 back | 4 cycle scale)`, `engine_present_set_options(h, {"scale": "ACTUAL" | "FIT_WIDTH" | "FIT" | "FILL", "hints": bool})`.
- `engine_present_state(h)` → `{active, page, screen, screenName, flow, flowName, flows: [{node, name, description}], overlays, history, canBack, canNext, canPrevious, scale, hints, device, hotspot, screenRect, events: [{type: "CHANGED"} | {type: "OPEN_URL", url, newTab}]}` (events drained).
- `engine_tick` / `engine_render` / `engine_next_frame_delay` / `engine_needs_frame` drive it: transitions animate on ticks, After delay timers ask for frames when due.
- Semantics: triggers On click (deepest hotspot pressed and released on), On drag (once, after 4 px), While hovering / While pressing (undone on leave / release: Change to swaps back, an overlay closes, a navigation goes Back), Mouse enter / leave / down / up, Key/Gamepad, After delay (armed when its frame or instance appears). Actions Navigate to (closes overlays, pushes history), Back (pops history; an overlay step closes it; played as the step's transition reversed), Open overlay (the destination frame's Position preset or Manual — relative to the hotspot —, its background, Close when clicking outside; never Smart animate), Swap overlay (keeps the place, not in history), Close overlay (the hotspot's overlay, else the topmost; its own animation), Change to (the closest instance showing a variant of the destination's set, swapped with `SWAP_INSTANCE`), Scroll to (the closest scrolling frame, `extraScrollOffset`, animated with the action's easing), Open link (an `OPEN_URL` event), Set variable (literal / alias / expression — + − × ÷, comparisons, AND / OR / NOT, NEGATE, STRINGIFY, TERNARY — written to every mode of the variable), Set variable mode (the page and the frames shown), Conditional (first true branch, else the condition-less one). Several actions run top to bottom. A click that nothing reacts to flashes the hotspots (Show hints on click).
- Transitions: Instant, Dissolve, Move in / out, Push, Slide in / out (the other screen moves 30 % and stays), Smart animate. **Smart animate** matches layers by name and place (`/Card#0/Title#0`: the name chain from the frame, with the index among same-named siblings), interpolates their frame-relative transform (angle + position for rigid transforms), size, opacity, solid paints and gradient stops, corner radii and stroke weight; draws the destination's own (interpolated) background, then the source's unmatched layers fading out, then the destination's layers (unmatched ones fading in). Change to with Smart animate interpolates the instance from its old state's snapshot.
- Scrolling: a top-level frame taller than the screen scrolls vertically (horizontally when its Overflow says so); nested frames with Overflow scroll their children within their content's extent (auto-layout end padding included); Fixed children of the top-level frame are drawn above, unscrolled; Sticky ones pin at the top. The wheel scrolls the deepest frame under the pointer that can move that way, else the screen.
- Screen: the page's device (`prototypeDevice` PRESET / CUSTOM size, Landscape swapped) or, with none, the frame itself cut to what the window shows; scaled by the scale option (Actual size, Fit width, Fit width and height — the default —, Fill screen) and centred on the page's `prototypeBackgroundColor` (default #1E1E1E).

**Rendering** (`render/PresentScene.h`, `render/PresentRender.cpp`): `Renderer::renderScene(doc, page, viewport, scene)` draws a list of items — a node's subtree placed by a matrix with per-item props overrides (scroll offsets, transitions, Smart animate), clipped to the screen, or a rectangle (overlay backgrounds, hotspot hints) — through the page's render tree and the canvas's own draw code. Two small hooks in `Renderer.cpp`: `propsAt(i)` (the item's override, else the document's props) in `drawNode` / `drawChildren`, and no culling / whole-screen layer bounds while a scene draws.

Tests: `engine/tests/unit/prototype.test.cpp` (11 cases: the fields read and written back; easings and springs; navigation, Back, history, next / previous, restart, flows; transitions drawing both screens then one; overlays — centred, background, close outside, Close overlay, Back; Smart animate matching and interpolation half way; While hovering Change to and its revert, Restart restoring the instance; overflow, Fixed, Scroll to, After delay; Key/Gamepad + Conditional; the scene through the renderer; prototype mode's noodle drag — connect, flow created, retarget, remove, undo). `npm run engine:test` 282 cases. `SHOT_ONLY=e8 npm run engine:shot` (noodles and the flow label in pixels, the presentation's background / frame / scroll / overlay dim / Smart animate's end).

Not done (vs Figma): device frames (bezel artwork) and the device's Model; the Responsive scale option (frames re-laid out to the window); On drag scrubbing a transition with the pointer; "Animate matching layers" with Move / Push / Slide (they run as the plain transition); Smart animate fading out the old state's unmatched layers on Change to (the old instance's layers are gone after the swap; they disappear), shadows / blurs and text content in Smart animate; Fixed layers of nested scrolling frames drawn above (they keep their layer order); variable-mode-specific Set variable; video triggers and actions; Scroll to's per-axis offset UI; noodles from instances' inherited interactions on the canvas; Back / Close overlay noodles (Figma draws none either for Back; it marks overlays with an icon).

## E7 export — API and status (2026-10-08)

Figma's export (help.figma.com 13402894554519 "Export formats and settings", 360040028114 "Export from Figma Design"), drawn by the engine: PNG / JPEG by the renderer offscreen, SVG and PDF by vector writers over the scene. Code: `engine/src/export/` (`Export.{h,cpp}` targets, bounds, sizes, readiness, the image store; `Scene.{h,cpp}` what the writers read — the renderer's drawing rules as paths and paints; `SvgWriter`, `PdfWriter`, `Deflate` a small zlib writer; `ExportApi.inc` the ABI, included at the end of `api/Api.cpp`). Additive elsewhere: `Renderer::setExporting` (transparent page, no greeking), `CMakeLists.txt` (the sources, `-Os` for them in wasm; the native tests link the system zlib to inflate what `Deflate` writes).

**ABI** (`engine/api/exports.txt`, `EngineExports.ts`, `Engine.ts`):

| Export | |
|---|---|
| `i32 engine_export(h, refs, settings, flags)` | `refs` a NodeRefList (`[]`: the current page's canvas), `settings` an ExportSettings as JSON with the schema's names (`imageType` PNG/JPEG/SVG/PDF, `constraint` {CONTENT_SCALE/WIDTH/HEIGHT, value}, `contentsOnly`, `useAbsoluteBounds`, `svgIDMode`, `svgOutlineText`, `svgForceStrokeMasks`). Result: PNG/JPEG → u32 width, u32 height, straight RGBA8 (JPEG flattened on white; the canvas on the page colour when it shows in exports); SVG/PDF → the file. Several refs: PDF → one page each; PNG/SVG → one image of them all (Copy as PNG/SVG of a selection). `E_BUSY` while fonts or images it draws are loading (requested; `EXPORT_ALLOW_PENDING` = 1 draws what there is). Synchronous — engine.md §10.8's `EXPORT_DONE` job/event isn't needed (the engine is in the view's thread and an export is one call). |
| `i32 engine_export_info(h, refs, settings)` | `{targets:[{ref,width,height,bounds}], images:[sha1], ready}` — sizes (PNG/JPEG: pixels), the images an SVG/PDF inlines, readiness (requests what's missing). |
| `i32 engine_export_image(h, sha1, kind, w, h, data, alpha)` / `void engine_export_clear_images()` | Images for the vector writers (the engine has decoded bitmaps only): kind 0 the file (SVG data URI), 1 a JPEG of the colour (PDF DCTDecode), 2 raw RGB; `alpha` a w×h plane (PDF soft mask). |
| `i32 engine_export_list(h, pageS, pageL)` | The page's layers with `exportSettings` (depth first) with their settings as JSON — the Export dialog. |

**What it does, as Figma does:** bounds = the layer's content (fills, strokes by alignment, drop-shadow offset + blur + spread, layer blur, the children a clipping frame keeps, text ink; masks clip what they mask) — a 100×100 rect with a (0, 4, 4) drop shadow exports 108×108 — or its box with "Include bounding box"; a slice = its box with its frame's content (contents only) or the page's; "Ignore overlapping layers" off = the page's layers within the bounds; nothing selected = the canvas on the page colour. Sizes: `1x/2x/…`, `512w`, `512h`; SVG/PDF 1x only; larger than 16384 px a side / 36 MP scaled down; rasters bigger than a texture drawn in 4096-px tiles. SVG in Figma's shape (`<svg width height viewBox fill="none">`, `<rect>/<circle>/<ellipse>/<path>` in file coordinates, black/white by name, `<g>` only where needed, `<defs>` last with `clip0_1_2`, `paint0_linear_1_2`, `filter0_d_1_2`, `mask0_1_2`, `pattern0_1_2`, `image0_1_2`; ids from layer names with `_2` for repeats): linear/radial gradients (userSpaceOnUse, gradientTransform when skewed), angular/diamond as CSS gradients in a clipped `<foreignObject>`, images as patterns with the file inlined, strokes centre as attributes / INSIDE-OUTSIDE inset-outset ("Simplify stroke", plain shapes) or outlined, or 2× under Figma's `path-1-inside-1` masks (simplify off), per-side weights and arrowheads outlined, Figma's filter chains for drop/inner shadows (spread by feMorphology) and layer blur, background blur as `backdrop-filter` in a `<foreignObject>`, alpha/luminance/vector masks, blend modes as `mix-blend-mode`, text as outlines or `<text>/<tspan>`. PDF 1.7 (1 px = 1 pt, one page per layer): paths, clips, strokes (inside/outside clipped), solid/axial/radial shadings, angular/diamond as PostScript-calculator function shadings, stop opacity via luminosity soft masks, images as XObjects (JPEG + soft mask) and tiling patterns, opacity/blend groups, alpha/luminance masks, layers with shadows/blurs as an image the renderer draws, text as Type 3 fonts of the glyph outlines with ToUnicode (selectable, copyable, not editable — Figma's "text as glyphs"); streams Flate-compressed.

**Tests:** `engine/tests/unit/export.test.cpp` (9 cases): zlib round trips, settings defaults, bounds (clip, Figma's shadow size, outside stroke, bounding box, 1x/2x/512w/512h, size cap, region, canvas), slices, SVG well formed + Figma's elements + **re-rendered by point sampling** against the document's geometry, SVG paints/strokes/filters/masks/ids/lines, SVG text both ways, PDF xref/streams/Type 3 ToUnicode/function shading, the ABI (pixels, JPEG on white, canvas on page colour, busy while an image loads, info, handed-in images inlined, multi-ref PNG/SVG/PDF, the export list). `npm run engine:shot` (`SHOT_ONLY=export`): every opaque pixel of 2x PNG exports = the canvas at 100 % (star, gradients, image, shadow, stroke), 17 layers' SVG drawn by Chromium = the PNG export (≥ 97 %, 93 % for photos/blur/outlined strokes/text edges), 9 layers' PDF drawn by macOS `sips` = the PNG (≥ 95 % of opaque pixels; Type 3 text 100 %), a 4960-px 4x export without seams.

**Open:** colour profiles are stored, not applied (exports are sRGB as drawn); "Image resampling" Basic (nearest) is stored, not used; PDF images re-encode as JPEG at the setting's quality (the original when it is an opaque JPEG); background blur in PDF rasterizes the layer alone (no backdrop); SVG `<text>` mode writes per-line `<tspan>`s (no per-glyph positions, so justified/kerned runs can drift); image paint filters (exposure…) are left out of SVG/PDF; a new slice doesn't get a default export setting yet (Figma adds 1x PNG).

## Figma parity round 4 — API (published first; stable)

What changed at the boundary in round 4 (status: "Status (2026-10-08): Figma parity round 4" below); everything in round 3's API still holds unless changed here.

- **`engine_load` / `engine_load_at` take kiwi only.** The interim JSON document is refused (`E_DECODE`, "engine_load takes a kiwi Message"). `Engine.load(message)` (TS) still takes a Message in the engine's JSON shape — memory sources, demos, tests — and encodes it with the shared codec first (`messageToKiwi` + `encodeMessage`; `message.currentPage` → `{page}`). `engine_apply_changes`, `engine_paste` and the library payloads still accept either encoding (the editor's facade methods pass Message objects; their kiwi twins stay preferred).
- **`engine_read_facets(h, idsPtr, count, mask)`** — the typed per-facet reads (Figma's generated `*FacetTsApiGenerated` bindings, in our flat-ABI form). `ids`: `count` (sessionID, localID) u32 pairs (a derived ref: `0xfffffffe` and its `engine_ref_id`); `mask`: facets, bit `1 << id`. Result: f64s — per node a presence slot (1 / 0), then each requested facet's record in id order (NaN for a node that isn't there). No JSON; nothing derived. The layout of every record is generated from `engine/tools/schemagen/fieldmeta.ts` into `<build>/generated/schema/facet_readers.h` (C++) and `src/renderer/src/engine/facets.generated.ts` (TS: `FACET_IDS`, `FACET_SLOTS`, `FACET_FIELDS`, `decode<Facet>`, `FACET_DECODERS`). Facets: `geometry` (type, visible, locked, opacity, transform, size, corners, constraints, auto-layout child), `shape` (arcData, count, starInnerScale), `stack` (auto-layout container, min / max size), `stroke` (weights, align, caps, joins, per-side weights, corner smoothing, blend, mask, clip), `text` (the scalar text fields). Values come in `engine_read_nodes`' shapes (enum names, `{x, y}`, `{m00 … m12}`, `{value, units}`, `{value: {x, y}}`), so a panel's cached node can be patched. TS: **`engine.readFacets(refs, facets): (Record<string, unknown> | null)[]`**.
- **Schema** (`schema/document.kiwi`, additive, no format bump): `VariableAnyValue.slotContentIdValue = 18` (`SlotContentId {guid}`) and `VariableDataType.SLOT_CONTENT_ID = 18`, Figma's names and numbers — a `.fig`'s slot assignments (`ComponentPropAssignment.varValue`) now survive import. `NodeChange.detachedSymbolId` round-trips in both forms (`{guid}` and `{assetRef}`).
- **Per-page loading, stricter** (Figma's dynamic page loading): `engine_load` resolves the bound values of the shown page and of the Internal Only Canvas only; another page's are resolved — and its instances derived — when it is first shown or read (as round 2's instances). The Internal Only Canvas is never derived whole: a read of an instance there (or of one of its sublayers, or a `READ_SUBTREE` read) derives the instances of that node's top-level container; reading a style, a variable or a main for its own fields derives nothing. Consequence for callers: a page never shown asks for no fonts at all (round 3 still asked for fonts of other pages' texts whose bindings resolved at load).
- **No other API change.** `engine_stats.nodeBytes` now counts the facets (round 4 item 4).

## Import fidelity (2026-10-08, branch fig-import-fidelity; merged after round 4)

Figma's own `.fig` files against Figma's own rendering (`scripts/fig-fidelity.mjs`, docs/data-impl.md "Import fidelity": numbers, method, what's left). Engine changes:

- **`engine_render_region(h, pageSessionID, pageLocalID, x, y, w, h, width, height, flags)`** (f64 region, u32 size): a page's world region drawn offscreen into width × height device px, the page colour behind, no overlays or frame titles; result as `engine_render_thumbnail`'s. TS: `engine.renderRegionPixels({page?, x, y, w, h, width, height})`. E_INVALID past the largest texture.
- **Override paths are Figma's** (docs/schema.md §5.1): a `guidPath` crosses nested instances only. The materializer named every frame on the way down (`[frame, frame, text]`), so a Figma override of a layer inside a frame of a component never applied (5,161 of 9,229 non-root overrides in the owner's file). `DerivedInfo.path`, override entries written by edits, `derivedSymbolData` paths all follow; files this engine wrote before are normalized at load (`normalizeOverridePaths`: an element that isn't the last and isn't an instance goes; entries that then name one sublayer merge). **`kDerivedDataVersion` 3** after the merge with round 4 (the branch's 2 and round 4's 1 both re-derive; 1's paths were tree paths, and both still meet the load-time conversions below).
- **Figma's derived data** (`kFigmaDerivedDataVersion` = 0x46494701, written by the import): read like the engine's own; its `derivedSymbolData` is sparse (only sublayers whose geometry isn't the main's, plus slot-content entries), so with that stamp the named sublayers take it and the others keep the main's (`StoredDerived::sparse`); the engine's own data must still name every sublayer.
- **NaN `stackCounterSpacing`** (Figma's "same as the column gap" for wraps) reads as absent — every child of such a frame was at NaN (stacks_wrap.fig's first frame drew empty).

- **`STRUCTURE_CHANGED {pageId, parents: Guid[] | null}`** — `parents`: the nodes (the page included) whose child lists changed this tick — the current and the previous parents of layers created, removed, reparented or reordered, instance sublayers included; `null` when the engine can't name them (a load, a page switch, too many). - **`engine_layer_changes(h, page, sinceVersion: f64)` → `{version, full, nodes, removed}`** (`Engine.layerChanges(page, since)`): the Layers rows changed since `sinceVersion` — the row of every node on `page` whose row data (`name`, `visible`, `locked`, `type`, `stackMode`, `stackWrap`, `resizeToFit`, `booleanOperation`, `isStateGroup`) or place (`parentIndex`, order) changed, plus the rows — with their complete, current `childIds` — of its current and its previous parents; and `removed`: the ids of nodes no longer in the document (any page; ignore unknown ones). `full: true` with the whole page's tree in `nodes` (and `removed` empty) when a delta can't be given: `sinceVersion` is older than the engine's change log keeps or ahead of it, or more than 4096 rows changed. Rows have the layer-tree shape (`guid`, `parentIndex.guid`, `type`, `name`, `visible`, `locked`, `childIds`, the optional flags). To apply: drop `removed`, upsert `nodes` by `guid` (replace a row's `childIds` with the one given), re-root at `page`. A reparented layer's subtree rows don't repeat (only its own row, for `parentIndex`); a created layer's whole subtree does. Instance sublayers appear and go as instances materialize (they are document nodes).
- **`engine_read_nodes(h, payload, flags)`** — the payload may be `{refs, fields?: string[]}`: `fields` restricts every node to those schema keys (`"fillPaints"`, `"strokePaints"`, `"visible"`, `"name"`, `"opacity"`, …; unknown keys ignored; `guid` and `type` always written; `childIds` still with INCLUDE_CHILD_IDS). New flags (`abi.ts`): `READ_SUBTREE = 2` — each ref is followed by every descendant, pre-order, children back to front (paint order; the refs' own order kept, a node once); `READ_VISIBLE_ONLY = 4` — with SUBTREE, hidden layers and what is under them are left out (the refs themselves are written whatever their visibility, so the caller can see `visible: false`). `Engine.readNodes(refs, {childIds?, fields?: string[], subtree?: boolean, visibleOnly?: boolean})`. Selection colors: `readNodes(selection, {fields: ["fillPaints", "strokePaints", "visible"], subtree: true, visibleOnly: true})` is the one read that replaces `readInside`'s level-by-level full reads (C++ writes only the paints; the selected nodes come first, each followed by its visible subtree).
- **Per-page derivation (lazy; Figma's dynamic page loading in spirit)**: `engine_load` materializes only the opened page's instances and verifies only its auto layout; another page's happen on its first `engine_set_current_page`, `engine_layer_tree` / `engine_layer_changes`, `engine_render_thumbnail`, or `engine_read_nodes` / `engine_component_info` of a node on it (`REQUEST_FONT`s for a page's fonts come then too — a page never shown asks for no fonts; "Missing fonts" therefore covers the pages shown so far). Undo / redo to a batch on another page and `GO_TO_MAIN_COMPONENT` go through `setCurrentPage` and derive first. Memory and load time scale with the pages visited. `engine_pages` is O(1). Nothing changes in what reads return once a page is derived.
- **Press rule (Figma)**: a press on a layer inside a selected layer (any depth) keeps the selection; a drag then moves the selection (so a selected instance covered by its children, or 20 selected instances, drag by any of their sublayers); a click — release without a drag — selects the pressed child (⇧: adds it). A press-drag whose selection has nothing movable (only instance sublayers, or only locked layers) opens no gesture: no transaction, no `DOCUMENT_CHANGED` / `NODES_CHANGED` / `COMPONENTS_CHANGED`, cursor `NOT_ALLOWED` while the button is down. Unchanged: ⌘-click deep-selects on the press; a press on an unselected layer outside the selection selects it on the press, as before.
- **Fonts**: no engine change. The desktop side slices a collection (TTC / OTC) to the one face asked for before it crosses the IPC (`src/main/fonts.ts readFont` / `sliceFace`, built in parallel in this round): a `ttcf` header whose entries all point at that face, so `engine_font_add_take(bytes, collectionIndex)` reads it unchanged (HarfBuzz opens the face at `collectionIndex` through the header). The 74.6 MB file of the owner's open becomes the ~10 MB of one face in the heap. Fonts bind lazily as before (`REQUEST_FONT` once per name; a page never shown asks for none, see per-page derivation).
- **No API change, faster**: `engine_component_info` and `engine_command_state` answer from a cache keyed by the document version (a render's five `componentInfo` calls cost one); local assets and library copies are found by key through an index kept on every write (`localAssetByKey`, `copyMainByKey`, `copyRootByKey`, preferred values by key: no document scan); instance counts likewise; the render tree re-places a moved / created / removed / shown / hidden subtree in its flat array instead of rebuilding the page's tree on every structural change.

## Libraries — review fixes (API published first; status at the end of this section)

The engine side of the review of the libraries round (a75036f). These are the calls the editor codes against; everything in "E6 libraries API" below still holds unless changed here.

- **(a) `importLibraryAssets(messages, {libraryKey, asNew?: boolean, keys?: string[]})`** — `asNew: true` writes a **new, complete copy** of the asked assets — new GUIDs, every child and variant, written by the engine's library writer (the read-only guard never drops its children) — even when copies of those keys are here (Update selected instance). The asked assets: `keys`, default the **first message's own asset** (`getPayloads` puts the asked one first). `result.assets[].id` for those keys is the new copy's id (`created: true`). Their dependencies are reused like any import (a copy here of the same library and key, preferring one at the payload's version); a dependency whose copy here lacks a node the new copy needs (a variant added since) gets a new copy of its own. Without `asNew`: unchanged (reuse). Inside an open batch (`txnBegin`) the import joins that step (no `E_BUSY`; `applyLibraryUpdate` too); otherwise it is a SYSTEM change as before. The result also has `images: string[]`: the image hashes the copies written or reused use (for the file's `blobRefs`).
- **(b) `applyLibraryUpdate(messages, {libraryKey, keys?, copies?: Guid[], redirects?: {fromKey, toKey, fromLibraryKey?}[]})`** — updates **every copy root** of each key in this file (several after Update selected instance), each matched node by node (below), in a deterministic order (by GUID); `copies` restricts it to those copy roots (the others of the same key stay as they are). A redirect re-points the copies of `fromKey` from `fromLibraryKey` (absent: from any library). Still **one undo step**; the result lists every copy written (`updated: true`) and every copy only reused (`updated: false`), each with its own id.
- **(c) Copies are identified by `(sourceLibraryKey, key)`**, never by key alone: imports, updates, redirects, the cross-file paste and reference fallbacks all look copies up by library and key, so a duplicated library file's assets (same keys, another FileKey) get copies of their own beside the original library's.
- **(d) `applyChanges(message, "system")`** (C flag `APPLY_SYSTEM = 8`, `abi.ts APPLY_SYSTEM`) — journaled and emitted to the store like a user change, **not an undo step**; for library bookkeeping (`libraryMoveInfo`, `publishedVersion`, `isPublishable`, `isSymbolPublishable`); still refused inside library copies. `E_BUSY` when called inside an open user batch (it would become part of that undo step). **`applyChanges(message, "restore")`** (`APPLY_USER | APPLY_EXACT`, `APPLY_EXACT = 16`) — for **Restore version**'s diff: one undo step, emitted, written exactly as given — library copies included (created, changed, removed), no detaching of bound values, no instance root overrides. Use it instead of `"user"` in VersionDialogs (#22).
- **(e) `markPublished(entries: {key, versionHash: string | null}[])`** — `versionHash` string: `publishedVersion` on that local asset, and on a published main (component or set) **`libraryMoveInfo` is cleared** (the move is done); `versionHash: null` (or `""`): the version removed that asset (hidden or deleted, then published) — its `publishedVersion` is cleared, so a cross-file paste treats it as unpublished (a new main / a copied-in main, R4 §8). One SYSTEM change per call (journaled, not undoable); `E_BUSY` inside an open batch.
- **(f) `libraryUsage()`** keeps listing every copy root separately, with its own `id`; the editor groups by `(libraryKey, key)`.
- **`encodeAssets`**: each `EncodedAsset` also has `images: string[]` (the image hashes its payload's nodes use; the top-level `images` is still the union).
- **versionHash (#4)** depends only on visible content: nodes in tree order (children by position) with their GUIDs, `parentIndex` GUIDs and `overrideKey`s left out; references to nodes inside the asset by their place in it, references outside it by the target asset's `key` (its GUID only while it has none: call `ensureAssetKeys` first, as the publish flow does), a reference to a node that isn't there (a preferred instance whose main was deleted, a missing style) by a fixed marker — never its GUID; preferred instances named by GUID or by key hash alike; bound values — fields a variable or a style sets — left out (the binding itself counts), so moving a main into a frame with another variable mode, an in-file cut + paste, or a changed **listed** variable's value doesn't change it. **Hidden dependencies fold in**: an asset's hash also covers the hashes of the hidden local assets its nodes use directly (Hide when publishing, a `_` / `.` name or a hidden set / collection, a copied-in main, a deleted-but-kept one: assets shipped only as `dependencyOnly`, never listed), each with its own hidden ones (a chain of hidden aliases); listed assets stay out (they are published, and updated, on their own). So a new value of `_Primitives/Blue` makes the listed `Tokens/Accent` that aliases it Modified (not what binds Accent), and a component bound to `_Primitives/Alias → Blue`, or nesting `_Private`, Modified. An asset with no hidden dependency hashes as before. The same content in two files or sessions hashes the same. `localAssets`, `encodeAssets` and the clipboard compute it the same way.
- **Cross-file paste of a published main (#5)**: the library copy it makes gets `version` = the versionHash of the content pasted, **computed in the source file**: `encodeSelection` writes each local keyed asset's versionHash as `version` on its clipboard node (as a payload does; a same-file paste drops it) and the paste uses it (a clipboard without it is hashed from its own nodes). Unchanged since the publish: exactly the published version, whatever the clipboard carries of what it uses (preferred instances it doesn't carry, hidden dependencies). Edited since: the hash of the unpublished content — never the published one — so the next diff lists the real published version as an update and `applyLibraryUpdate` replaces the copy. Preferred instances in the clipboard: mains it carries by GUID, others by key (as in payloads); in the other file a GUID that came along is mapped, one that didn't is dropped (never this file's node with that GUID), keys stay.
- **Same-file cut + paste of a main** (it gets a new GUID, keeps its key): preferred instances that named it by GUID are re-pointed at it in the same undo step, so what lists it keeps its hash.
- **Payload order (#23)**: each message's own asset (its first node's subtree) wins over copies of that asset embedded in other messages; an embedded copy is used only when no message of its own is given, and then whole (never mixed with another version of it).
- **Matching (#1)**: an update (and a reuse, and Move to this file's relink) matches copy nodes top-down: the root to the copy root, each child only among its mapped parent's children, each node used once — components and variants by the library GUID they carry (`publishID`), then by key + name; other layers by key. Variants that share keys (Add variant, Duplicate) stay distinct. A component copy whose `publishID` the new version doesn't have (a deleted variant) is never taken by key or name for another component (a variant added in the same publish with the same key gets a node of its own). Every variant of a copy carries its library GUID: a copy made from a copy (a paste from a file that has it, a library using another one) keeps the `publishID`s the source carries.
- **A deleted variant (data.md §9.6)**: when an update of a set copy no longer has a variant, its copy stays while anything uses it (an instance, an override, a copy not updated): moved out of the set onto the internal canvas as a library copy of its own (`sourceLibraryKey` = the set copy's library; its `key`, `publishID`, `version` kept), so its instances keep rendering it. `libraryUsage` lists it (its key is the variant's, which the library's manifest no longer has: the editor's diff shows it as removed; Detach and Restore component work on it). One not used is removed, as before. Undo puts it back in the set.
- **Nothing points at nothing (#3)**: a copy kept as it is that lacks a node that a written copy — or a cross-file paste's own nodes — refers to (a variant added since) comes in as a new copy (the old one keeps its users); a main copied in from another file (unpublished) that lacks it is copied in again (later pastes take the newest). `Editor::unresolvedReferences()` (C++; tests) counts the main references the last import / update / cross-file paste still could not resolve (left pointing at nothing — a payload or clipboard that lacks the main); a debug build also says so on stderr.
- **`componentInfo` preferred values named by key** (a copy's, a .fig's, a clipboard's) resolve within the main's own library — that library's copies (variants included); for a local main, this file's own asset, else a copy (first by GUID) — never another library's copy with the same key.
- **`variableResolvedType`** is always written for VARIABLE nodes (BOOLEAN included) in `encodeDocument`, payloads and reads.

## E6 libraries API — names (published first; stable)

The engine side of docs/data.md §9 and docs/schema.md §8. Status: see "Status: E6 libraries" below.

**Node fields** (`NodeFields`, schema names): `key` (40 lowercase hex, every asset: SYMBOL, component set, style, VARIABLE_SET, VARIABLE), `publishedVersion` (local asset: its `versionHash` at its last publish), `sourceLibraryKey` (library copy root: the library's FileKey), `publishID` (library copy: the asset's GUID in the library file; every SYMBOL / set inside a copy carries its own), `version` (library copy: the `versionHash` it was copied at), `libraryMoveInfo {oldKey, pasteFileKey}` (a published main cut from another file and pasted here), `isSymbolPublishable` (SYMBOL: false = Hide when publishing; sets / styles / collections / variables use `isPublishable`).

**Types** (`Engine.ts`):
- `AssetKind = "COMPONENT" | "COMPONENT_SET" | "STYLE" | "VARIABLE_COLLECTION" | "VARIABLE"` (data.md §9.1; a variant is a COMPONENT with `componentSetKey`).
- `LocalAssetInfo = {id: Guid, key: string ("" until ensureAssetKeys), kind, name, description, styleType?, resolvedType?, componentSetKey?, componentSetId?, collectionKey?, collectionId?, hiddenFromPublishing (Hide when publishing, or a name starting with "." / "_"; a hidden set / collection hides its members), softDeleted (deleted but kept for what uses it: "Removed" when publishedVersion is set), versionHash (40 hex), publishedVersion: string | null, dependencies: string[] (keys of this file's assets it needs: nested components' mains or sets, styles, variables, their collections), containingFrame: {pageId, pageName, frameId?, frameName?} | null}`.
- `EncodedAsset = LocalAssetInfo & {dependencyOnly: boolean, message: Message}` — `message` is a NODE_CHANGES Message (engine JSON; `engineMessage.ts` converts it to kiwi for `AssetPayload.message`) holding the asset's nodes **and every node it depends on** (the closure: nested mains, styles, variables, collections, library copies it uses), all CREATED with the library file's GUIDs, vector blobs in `blobs`; each asset root in it carries its `key` and its `versionHash` as `version`. Images travel by hash (`images`).
- `LibraryImportResult = {status: Status, assets: [{key, id: Guid, kind, libraryKey, version, created: boolean, updated: boolean}]}`.
- `LibraryAssetUsage = {id, key, kind, name, libraryKey, version, publishID, usageCount, componentSetKey?, collectionKey?, styleType?, resolvedType?}`.

**Calls** (`Engine.ts`; C ABI in parentheses; JSON in and out):
- `setFileKey(fileKey: string)` (`engine_set_file_key(h, ptr, len)`): this file's FileKey; clipboard Messages carry it as `pasteFileKey`, and a paste whose `pasteFileKey` differs is a cross-file paste.
- `ensureAssetKeys(refs?: Guid[]): {id, key}[]` (`engine_ensure_asset_keys(h, refsPtr, refsLen)`): gives every local asset in `refs` (default: all) that lacks one a fresh key — a SYSTEM change (journaled, not undoable). Keys never change after that: kept through edits, renames, moves, cut + paste in the file and undo; duplicates (⌘D, ⌥-drag, copy + paste of a set, Duplicate variable / collection) get none (a fresh one on request).
- `localAssets(): LocalAssetInfo[]` (`engine_local_assets(h)`): every local asset, publishable or not, deleted-but-kept ones included.
- `encodeAssets(keys: string[]): {assets: EncodedAsset[], images: string[]}` (`engine_encode_assets(h, keysPtr, keysLen)`; keys JSON array): the assets asked for plus their dependencies (`dependencyOnly: true` for those not asked for); a variant's key encodes its whole set. `versionHash` = SHA-1 (hex) of the asset's own nodes, canonical (tree order, schema field order; GUIDs, `overrideKey`s, bound values, derived fields, its place and position on the page, `sortPosition`, publishing flags, `key` / `version` / `publishedVersion` left out), with the hashes of the hidden assets it uses folded in (see "Libraries — review fixes"): it changes only when the asset's content, or a hidden asset's it ships with, changes. Each asset also lists `images` (its payload's image hashes).
- `markPublished(entries: {key, versionHash: string | null}[]): Status` (`engine_mark_published(h, ptr, len)`): writes `publishedVersion` on those local assets after a successful publish (SYSTEM, not undoable) and clears `libraryMoveInfo` on the published mains; `versionHash: null` clears `publishedVersion` (the version removed the asset). Pass every asset of the new version, `dependencyOnly` ones included, and a null entry for every asset it removed: a cross-file paste treats an asset with `publishedVersion` as published (a library copy), one without as unpublished (copied in).
- `importLibraryAssets(messages: Message | Message[], options: {libraryKey: string}): LibraryImportResult` (`engine_import_library_assets(h, msgPtr, msgLen, optsPtr, optsLen)`; msg = a Message, an array of them or `{messages: […]}`; no `libraryKey`: `E_INVALID`): puts read-only copies on the internal canvas `0:2` (fresh GUIDs, every node's `overrideKey` = the library node's effective key, roots marked `sourceLibraryKey` / `key` / `publishID` / `version`); an asset whose copy is already here (same library and key; of several, the one at the payload's version, else the first by GUID) is reused, never downgraded or upgraded — `asNew` writes a new copy instead (see "Libraries — review fixes"); a payload root that is already a library copy in the library file (a library using another one) keeps its own `sourceLibraryKey`; one of this file's own assets (its `sourceLibraryKey` = `setFileKey`) is the local asset itself. A SYSTEM change (journaled, not undoable); `VARIABLES_CHANGED` / `STYLES_CHANGED` follow. Then instances (`INSERT_INSTANCE {main: <copy id>}`), `APPLY_STYLE {style: <copy id>}` and `BIND_VARIABLE {variable: <copy id>}` use the copies exactly like local assets.
- `applyLibraryUpdate(messages, options: {libraryKey, keys?: string[], copies?: Guid[], redirects?: {fromKey, toKey, fromLibraryKey?}[]}): LibraryImportResult` (`engine_apply_library_update(…)`, same layout): replaces every copy of `keys` (default: every asset root in the messages that has a copy here; `copies`: only those copy roots) with the new payloads — nodes matched top-down (components by `publishID`, layers by `overrideKey` among their parent's children), GUIDs kept, so instances keep their overrides and links, bound layers and style users re-resolve — and adds missing dependencies; `redirects` (Move to this file) re-point the copy of `fromKey` at `toKey`'s payload in the messages (same GUIDs, new `sourceLibraryKey` / `key` / `publishID`; its users keep their links and overrides); when `toKey` is **this file's own** asset (it moved here), the copy's users — instances, nested instances, style and variable references — are relinked to it (nodes matched by key, so overrides survive) and the copy is removed (messages may be empty then). Asked again with the same versions: nothing written. **One undo step**, labelled "Update library assets".
- `libraryUsage(): LibraryAssetUsage[]` (`engine_library_usage(h)`): every library copy in this file with its `version` and how many layers use it (instances; style users; bound layers and aliases). A copy whose asset was removed from its library stays and keeps rendering.
- Reads gain library fields: `VariableCollectionInfo`, `VariableInfo`, `StyleInfo` add `remote: boolean`, `libraryKey: string | null`; `variableCollections({includeRemote?: boolean})`, `variables(collection?, {includeRemote?})`, `styles(type?, {includeRemote?})` list local assets only unless `includeRemote` (a remote collection's id given to `variables` lists its variables); `variable(id)` and `variableModes(ref)` cover remote ones. `ComponentInfo.main` adds `remote: {libraryKey, key, version} | null` and `copied: boolean` (a main copied from another file onto the internal canvas); `canPush` is false for them.
- C ABI: `engine_variable_collections(h, flags)`, `engine_variables(h, collPtr, collLen, flags)` and `engine_styles(h, type, flags)` gained `flags` (INCLUDE_REMOTE = 1; `abi.ts INCLUDE_REMOTE`); `styleUsage` / `usageCount` count this file's layers only (a copy's own layers are not uses).
- Read-only: `setProps`, variable / style / component commands on a library copy (or anything inside one: `ref`, `refs`, `parent`, `collection`, `variable(s)`, `style(s)`) answer `E_READONLY` (-6) and change nothing; `moveNodes` into or out of one answers 0; user and system `applyChanges` skip writes into copies (`"restore"`, APPLY_EXACT, writes them). Commands that only use a copy (INSERT_INSTANCE, SWAP_INSTANCE, APPLY_STYLE, BIND_VARIABLE, SET_VARIABLE_MODE, CREATE_STYLE from a layer) work. `GO_TO_MAIN_COMPONENT` is disabled for an instance of a copy or of a copied main.
- **Restore component** of a removed library component (data.md §9.6): `RESTORE_COMPONENT {ref: <instance or the copy>}` makes the copy (its whole set) this file's own main on the current page, in the middle of the view: library identity cleared (`sourceLibraryKey`, `key`, `version`, `publishID`; a key on request), instances stay linked, one undo step "Restore component"; also for a copied main. The engine doesn't know an asset was removed: the editor offers it (`commandState(RESTORE_COMPONENT)` stays for soft-deleted local mains). The generic path does the same: a user change that clears a copy root's `sourceLibraryKey` is the one write a copy takes.

**Clipboard (cross-file, R4 §8, data.md §9.5)**: `encodeSelection({cut?: boolean})` (`engine_encode_selection(h, flags)`, flag CUT = 1) writes `pasteFileKey` and `isCut`, and adds after the selection every main component, component set, style, variable and collection it references (outside `clipboardSelectionRegions`). `paste` in another file: an instance of a **published** main (it has `publishedVersion`) or of a library copy becomes an instance of a library copy (`sourceLibraryKey` = the source file, or the copy's own library); an instance of an **unpublished** main gets a copy of the main as a local component on the internal canvas (`copied: true` in `componentInfo`; reused by later pastes); styles / variables follow the same rule (published or library → library copy; unpublished → copied in as local styles / variables, reused by later pastes). A main pasted itself: published and not cut → an instance of its library copy; published and cut → a new main without a key (a new one on request) and `libraryMoveInfo {oldKey, pasteFileKey}` (a main that already carries `libraryMoveInfo` — moved before, not published since — keeps it when cut again); unpublished → a new main; a component set → a new set (its published variants marked the same way when cut). The pasted main's layers keep the source's keys (`overrideKey`), so Move to this file relinks instances with their overrides. In the same file, a cut main keeps its key (pasted a second time: an instance of it); one whose source was soft-deleted (it had instances) is moved back, keeping its GUID, key and instances. Without `setFileKey` on both sides (no `pasteFileKey`, or the same one) a paste is a same-file paste, as before. A library copy made by a paste of a published main is made from the clipboard's content, and its `version` is that content's hash (computed by the source's `encodeSelection`, carried as the clipboard node's `version`): the published version when the main is unchanged since its publish, else the hash of the unpublished content, which never equals the published one — the next diff offers the published version as an update and `applyLibraryUpdate` replaces the copy.

### How it works (decisions)

- **One writer for copies.** `writeImports` takes "plans" (a source root → a COPY or a LOCAL asset, a target to reuse or replace) and writes them in the open transaction: library imports (SYSTEM), updates (USER, one step) and cross-file pastes (inside the paste's step) all use it. Source GUIDs map to fresh ones (or, for a replaced or reused copy, to its existing nodes, matched top-down: the root to the copy root, each node only among its mapped parent's children and each existing node once — components by `publishID`, then key + name, then key; other layers by key; a key unique in the copy as a last resort), so GUIDs that collide across files, and variants that share keys, never matter; references outside the payload resolve to an existing copy by `publishID`, then by library + key, else to nothing (never to a local node that happens to share the GUID). A copy that is kept as it is but lacks a node a written plan refers to (a variant added to its set since) is written as a new copy, so a reference never points at nothing. Several copies of one asset (after Update selected instance): an update writes each; references from other plans go to the first by GUID.
- **The library code's writes aren't user edits** (`libraryWrite_`): no read-only refusal, no detaching of a bound value whose resolved value changed, no instance root overrides on a copy's nested instances — but they are recorded for undo.
- **Read-only** is a guard in `write()` for user transactions (`hasLibraryCopies_` keeps it free in files without copies), plus `E_READONLY` answers in `setProps` and the command dispatcher.
- **versionHash** = SHA-1 over the asset's real subtree in tree order (children by position), each node as the engine's canonical JSON with the non-content fields cleared — its own GUID, its parent's (as its place in the tree), `overrideKey`, values a variable binding or a style sets (`Editor::clearBoundValues`) — references inside the asset by their place in it, references outside by the target's key, blobs hashed by content. Not the kiwi bytes (data.md §9.1 says "the payload encoding"): the engine's JSON is deterministic and field-ordered too, and the hash only has to be stable across engines of this build. A variable's hash is its own node; its collection's is the collection's. The same hash is computed over a clipboard's nodes (cross-file paste, `HashView`).
- **Payloads are per asset with their whole closure** (data.md: "the subtree + its blobs"; we add the dependencies so one payload imports on its own). The store may dedupe by `(key, versionHash)`; on import each message's own asset wins over copies of it embedded in other payloads (those can be older: a payload is never rewritten while its asset's hash stays the same), and an embedded asset is taken whole from the first message that has it.
- **Copies in a paste** come from the clipboard's own nodes (copySelection appends the referenced assets), not from the store: offline and immediate. Their `version` is the hash of the content they were made from (the published version when it is the published content).
- **Copied mains** (an unpublished main pasted from another file) are local SYMBOLs on the internal canvas: editable through the API, hidden from publishing (shipped only as dependencies), found again by later pastes through their `publishID` (the source GUID) + type + name.
- **Size**: +103 KB of Wasm for this round (the library code, the hashing, the clipboard closure).

### How it works (decisions)
- **Data** (`scene/Node.h`, `scene/CodecJson`): the field mask is 128 bits now (74 properties). Paints are fully typed (gradients, images, filters; other members kept in `Paint::extra`), as are effects, vector data (`Bytes` = shared immutable blob bytes), arcs, stroke caps / joins / dashes, per-side weights, corner smoothing, masks, blend modes, layout guides. A Message's blobs travel as base64 (`codec::BlobsIn` / `BlobsOut`); `fillGeometry` / `strokeGeometry` are derived and dropped on read (the engine computes them).
- **Geometry** (`geometry/`): `Path` (Figma's commandsBlob both ways, bounds, flattening, cubics → quadratics within a tolerance), `VectorNetwork` (the blob both ways, byte for byte; regions → fills, chains → strokes, per-vertex corner radius, from a path), `Shapes` (Figma's radius clamp, the squircle for corner smoothing — the published Figma construction, arcs / pies / donuts, polygons and stars stretched to their box, rounded corners), `Stroker` (polyline stroking where every segment, join and cap is its own positively wound piece unioned by NONZERO: robust on any input; miter limit, round / bevel joins, caps, arrowheads, dashes by arc length), `Boolean`, `NodeGeometry` (the per-node cache: what a node's fills and strokes cover, keyed by its inputs; booleans computed live from their operands; text from its glyph outlines).
- **Booleans: Clipper2** (2.0.1, Boost licence, vendored in `third_party/clipper2`, only `clipper.engine.cpp` compiled, `USINGZ`) on the flattened operands, with **curve recovery**: every flattened point carries its source curve and parameter in Clipper's Z, intersections get the parameters on both curves (Z callback), and runs along one source curve are turned back into that curve's exact Bézier section. Booleans keep their curves (two circles union to arcs of the original cubics) and Clipper does the hard part (overlaps, touching edges, self-intersections). This replaces engine.md's planned paper.js port (§12, §14 Q4).
- **Paths on the GPU: curve coverage, not stencil-then-cover.** E3's glyph method extended to every path (`render/CurveCache`, `gfx/gl/Shaders.h kPath*`): a path's quadratics in one RGBA32F texture with horizontal and vertical **bands** (each band's curves sorted for early exit, so thousands of curves stay cheap), one instanced quad per path, per-pixel coverage from a ray along +x and one along +y, **NONZERO or ODD**, and an optional second path multiplied in or out (INSIDE / OUTSIDE strokes = the 2×-weight outline × the fill's coverage). Anti-aliased analytically: no MSAA, no stencil, crisp at every zoom (the approximation level follows the zoom by powers of two). `render/CurveCoverage.h` is the same math in C++ for the tests. Decided over engine.md §6.3's stencil + Loop-Blinn + MSAA (the canvas has no MSAA; §14 Q3 is moot).
- **Paints**: one instance layout for shapes, paths and glyphs (`render/DrawInstance.h`, 7 vec4s) with the paint's matrix (local → paint space); gradients from a ramp atlas (256 premultiplied texels per stop list, interpolated premultiplied, dithered); LINEAR `t = x`, RADIAL `2|p − ½|`, ANGULAR `atan2` from +x clockwise, DIAMOND `2(|x − ½| + |y − ½|)` in Figma's gradient space; images by `imageScaleMode` (FILL cover, FIT contain, STRETCH = Crop through `Paint.transform`, TILE at `scale`, `rotation` in 90° steps) with the adjustments as shader math (curves unverified against Figma). A paint with its own blend mode goes through a layer.
- **Images** (`render/ImageCache`): the module-wide registry (bitmap ids or RGBA) + per-renderer mipmapped textures, 512 MB budget, least recently drawn out (re-uploaded from the registry). REQUEST_IMAGE once per hash. While loading, Figma's grey `#E6E6E6`.
- **Layers and effects** (`render/Renderer.cpp`): a node needing one (opacity on a container or on several paints, a blend mode, layer blur, shadows the analytic path can't do) is recorded into a layer — its own target from a pool, sized to its device bounds — run before its parent's pass, post-processed and composited (`kComposite*`: opacity, all 18 blend modes from the backdrop via copyTexSubImage, alpha / luminance masks, drop shadows knocked out by the node, inner shadows). **Shadows**: rectangles and frames with an opaque fill (and clipped children) use Evan Wallace's analytic blurred rounded rectangle (drop and inner, spread, per-corner radius); anything else (ellipses, vectors, text, groups — structure.fig's "Group 2") renders its alpha, dilates / erodes by the spread, blurs (σ = radius / 2, separable Gaussian, halving the image while σ > 8 texels) and composites. **Layer blur** blurs the layer; **background blur** copies the backdrop, blurs it and paints it into the node's shape before its fills. **Masks** (a child with `mask`): the mask and the layers above it each into a layer, composited by the mask's alpha or luminance (OUTLINE: its geometry, opaque). Shadow offsets don't turn with the node (as Figma). The canvas is RGBA now (`alpha: true`): WebGL2 refuses to copy an RGB framebuffer into an RGBA8 texture.
- **Frame titles** read the page colour's luminance: white at 70 % on dark pages (Figma's secondary text on dark), black at 50 % on light ones (`Renderer::titleColor`).
- **Editing** (`editor/VectorEditing.cpp`, `VectorCommands.cpp`, `PaintEditing.cpp`): the shape tools (L / ⇧L / polygon / star: Figma's defaults — lines a 1 px black centre stroke, polygons 3 points, stars 5 at 38.2 %, ⇧ at 45°); the Pen (a click a point, a drag its mirrored handles, back on the first point a closed filled loop, a click on a segment splits it, each point one undo step, Esc ends the path, then the Pen, then the mode); the Pencil (simplified within a screen pixel, Catmull-Rom curves, 2 px round strokes); vector edit mode (vertices, segments, handles with the vertex's mirroring — ⌥ breaks it —, ⌘ / BEND to bend a segment or toggle a point sharp ↔ smooth, marquee and lasso, paint bucket, ⌫ delete-and-heal, arrows nudge, ⌘A, the box refitted after every edit, a shape becoming a VECTOR at its first edit); booleans (the style from the topmost layer, the bottom one for Subtract — unverified against Figma), Flatten (into the topmost layer's GUID), Outline stroke (a filled shape keeps its fill and gets a new vector for its stroke; otherwise it becomes the outline; the outline is polylines at 0.02 px), Use as mask (several: grouped with the bottom one as mask), Place image; gradient handles (start / end, or centre / end / width; the width handle stays square to the axis; stops on the line; a click adds one in the colour there; ⇧ snaps to 10 %).

### How it works (decisions)

- **Drawing** (`render/GlyphCache.*`, `render/TextRender.cpp`, `gfx::ShaderId::Glyph`): every glyph's quadratic curves live in one RGBA32F texture (two texels per curve); a glyph is one instanced quad over its bounds and the fragment shader computes coverage from the curves directly — a ray along +x and one along +y per pixel, roots classified by the endpoints' sides (Lengyel, JCGT 2017), each crossing's distance into the pixel as coverage, the two rays blended by proximity. ## What works (E0 + E1; E2 is in the status section)

**Scene graph.** A flat table of nodes keyed by GUID (`"s:l"`). Each node has these typed properties, named as in the schema:
- `type`, `name`, `visible`, `locked`, `opacity`
- `transform` (2×3, relative to the parent), `size`
- `fillPaints` and `strokePaints` (solid colours, list-shaped), `strokeWeight`, `strokeAlign`
- the four `rectangle*CornerRadius` fields plus `cornerRadius`
- `frameMaskDisabled`, `resizeToFit`
- `parentIndex {guid, position}`
- on CANVAS only: `backgroundColor`, `backgroundEnabled`, `internalOnly`

Rules:
- Children are derived by sorting `position`, ties broken by GUID.
- Node types: DOCUMENT, CANVAS, FRAME, ROUNDED_RECTANGLE, ELLIPSE. RECTANGLE and GROUP are accepted on import. A group is FRAME + `resizeToFit`.
- A change is a node id plus the fields it touches. `apply()` returns the inverse.
- CREATED for a live GUID replaces the node.
- Cycles are refused.
- An orphan waits until its parent arrives.

**Transactions and undo** (docs/engine.md §9). Every edit runs inside a transaction (USER, GESTURE, UNDO, REDO, REMOTE or LOAD):
- Writing an equal value does nothing.
- A committed USER, GESTURE, UNDO or REDO transaction emits exactly one `DOCUMENT_CHANGED` Message. That Message holds one NodeChange per node with only its changed fields; creations carry their full state and removals come children first.
- A gesture is one undo step: inverses fold, so the first value wins. Key-repeat nudges merge into one step.
- Undo and redo restore the selection.
- Esc, blur and pointer-cancel roll the gesture back exactly and emit nothing.
- Panel scrubs use `txnBegin`/`txnCommit`.
- When a key would grow past 24 characters, the siblings are rebalanced inside the same transaction (§10.3).
- The undo stack is capped at 1,000 steps.

**Renderer** (ours, over `gfx::Device`):
- Shapes are instanced SDF quads with analytic AA: rect, rounded rect with per-corner radii, ellipse. Fill and stroke (inside, centre or outside) are drawn in one pass, premultiplied, with opacity.
- Geometry is composed in doubles on the CPU, camera included, so the GPU only sees screen-space floats.
- Frame clipping uses scissor when the frame is axis-aligned and square, and stencil (nested) when it is rounded or rotated.
- Render on demand: nothing runs while idle.
- DPR uses the canvas's real backing size.
- Strokes draw over a frame's content.
- Off-screen nodes are culled.
- The page colour is used, or the theme's when the page uses Figma's default `#F5F5F5`. Dark is `#1E1E1E`.
- 10,000 rects are drawn in one draw call.

**Overlays** (§6.11):
- Hover outline is 2 px and follows the shape.
- Selection box is 1 px and drawn along the rotated box. Multi-selection shows each layer's box plus the combined box.
- 8×8 white handles with the selection-colour border. They are hidden when the box is under 24 px on screen.
- The size badge is a 16 px pill placed 6 px below the box. Its `W × H` text comes with E3.
- Marquee is a 10% fill with a 1 px border.
- The selection colour is `#0D99FF` in light and `#0C8CE9` in dark (§6.11).
- 1 px lines snap to device pixels.

**Camera:**
- The wheel pans; ⇧ pans sideways.
- Pinch, or ctrl/⌘ + wheel, zooms around the pointer by `exp(−dy·0.01)`.
- Space-drag, middle-drag and the H tool pan.
- Zoom range is 0.02–256.
- Zoom to fit (⇧1), to the selection (⇧2), 100% (⇧0 / ⌘0), ⌘+ and ⌘−. These commands land the page on whole device pixels.

**Hit-testing and picking** (§8.2, ported from `picking.ts`):
- Geometry-accurate for rounded rects and ellipses.
- A stroke counts within max(half its width, 4 CSS px).
- A frame is hit by its box only when it shows a fill or stroke, or is top-level.
- A group is hit only through its children.
- Clipped children outside their frame don't hit.
- Hidden nodes are skipped, and the path is cut at the first locked node.
- Picking: a top-level frame's child first. A selected layer opens to its children, and siblings of the selection are picked at their own level. ⌘ picks the innermost layer.
- Click, ⇧-click (toggle) and marquee: live, ⇧ additive. A partly covered frame contributes its children, and a marquee started on a frame's background works among that frame's children.

**Gestures and tools:**
- Move: 3 px threshold, ⇧ locks the axis, whole pixels.
- Resize from 4 corners plus edge zones: ⇧ keeps the ratio, ⌥ resizes from the centre, dragging past zero flips the node (negative scale). Several layers scale as one box, and a group resizes its children.
- Rotate from 16 px zones outside the corners; ⇧ snaps to 15°.
- Draw with F/A (frame), R (rectangle) and O (ellipse): ⇧ makes a square, ⌥ draws from the centre, and a click makes a 100×100 shape inside the innermost frame under the press. Figma's defaults apply: a frame gets a white fill and the name "Frame N"; rectangles and ellipses get `#D9D9D9` and the names "Rectangle N" / "Ellipse N"; all get a 1 px inside stroke weight. After drawing, the tool goes back to Move.
- Keys the engine handles itself: arrows (nudge, ⇧ ×10), Esc (cancel, then parent, then deselect), Enter (children), ⇧Enter (parent), Tab / ⇧Tab (siblings), Space.
- Every other key goes to TS's shortcut table (`shortcuts.ts`): V F A R O H, ⌘Z, ⇧⌘Z, ⌘Y, ⌫, ⌘A, ⇧0/1/2, ⌘0, ⌘+, ⌘−, ⌘], ⌘[, ⌥⌘], ⌥⌘[, ⇧⌘L, ⇧⌘H.

## The C ABI

Calls are flat `extern "C"` functions; there is no embind. The ABI version is 1, and `api/exports.txt` lists everything. In wasm32, pointers and handles are u32; natively they are `uintptr_t`, so the native tests can call the same functions. Payloads are UTF-8 JSON in the shapes of `schema/document.kiwi` (see below).

| Function | Notes |
|---|---|
| `engine_abi_version`, `engine_alloc/free`, `engine_result_ptr/len`, `engine_events_flag_ptr`, `engine_last_error` | Module. Results go to one result slot, valid until the next result. The events flag is a u32 in memory, non-zero while events are queued. |
| `engine_create(selector, opts, len)` / `engine_destroy` | `"#engine-canvas"`, or 0 for headless. `opts` is `{sessionID, theme}`. |
| `engine_load(h, msg)`, `engine_apply_changes(h, msg, flags)`, `engine_encode_document`, `engine_pages`, `engine_set_current_page` | A Message is `{type, sessionID, nodeChanges}`. Flags: `APPLY_USER` 1, `APPLY_REMOTE` 2, `APPLY_LOAD` 4. |
| `engine_set_viewport(h, cssW, cssH, dpr, pxW, pxH)`, `engine_set_camera`, `engine_get_camera`, `engine_set_theme` | The engine sets the canvas's backing size. |
| `engine_pointer(h, type, x, y, button, buttons, mods, pressure, clicks, pointerType, t)` | Type: DOWN 0, MOVE 1, UP 2, CANCEL 3, ENTER 4, LEAVE 5. Returns HANDLED 1 \| CAPTURE 2. |
| `engine_wheel(h, x, y, dx, dy, deltaMode, mods, flags)` | `PINCH` = 1 |
| `engine_key(h, type, keyCode, codepoint, mods, repeat)`, `engine_modifiers`, `engine_blur` | `keyCode` is the index into `Keys.h` / `keyCodes.ts`. Returns HANDLED 1. |
| `engine_set_tool(h, tool)`, `engine_set_hover(h, refs)` | Tools follow §8.4's order. |
| `engine_tick`, `engine_render`, `engine_needs_frame`, `engine_next_frame_delay`, `engine_gl_context_lost/restored` | Render on demand. |
| `engine_get_selection`, `engine_set_selection`, `engine_read_nodes(h, refs, flags)`, `engine_hit_test` | `INCLUDE_CHILD_IDS` = 1 |
| `engine_set_props(h, refs, change, flags)`, `engine_txn_begin/commit/cancel`, `engine_command(h, id, args)`, `engine_command_state` | Commands are in `Commands.h` / `abi.ts`. Args: `{dx, dy}` (NUDGE), `{page: "s:l"}` (DELETE_PAGE, DUPLICATE_PAGE). |

## The TS API

```ts
const engine = await Engine.create(canvas, { sessionID, theme: "DARK" }); // canvas null = headless
engine.load(message);                         // or loadDocument()
engine.applyChanges(message, "user" | "remote" | "load");
engine.pointer(...) / wheel(...) / key("down", e.code, e.key, mods, e.repeat) / modifiers() / blur();
engine.setTool("RECTANGLE"); engine.undo(); engine.redo(); engine.command("ZOOM_TO_FIT");
engine.getSelection(); engine.setSelection(["1:5"]); engine.readNode("1:5", { childIds: true });
engine.setProps(["1:5"], { opacity: 0.5 }); engine.txnBegin("Opacity"); …; engine.txnCommit();
engine.onDocumentChanged((changes, e) => persist(e.message));   // one Message per commit
engine.onSelectionChanged((s) => …); engine.onCursor((kind, angle) => …); engine.on("CAMERA_CHANGED", …);
engine.encodeDocument(); engine.hitTest(x, y); engine.stats(); engine.destroy();
engine.command("GROUP"); engine.command("DELETE_PAGE", { page: "0:3" });
engine.moveNodes(["1:5"], "1:1", 0);                            // Layers drag: paint order, counted without them
const clip = engine.encodeSelection(); engine.paste(clip!, { inPlace: true });
```

- **Event pump.** After every call, the facade reads the events flag from memory. If it is set, the facade drains the queue and dispatches the events synchronously after the engine has returned. A handler may call the engine again: its events are queued behind the current ones.
- **Frames.** Any call that leaves the engine wanting a frame schedules one `requestAnimationFrame`, which runs tick and then render.
- **`CanvasController`** (used by `EngineCanvas`) forwards pointer events (with pointer capture), wheel events (`passive: false`, `ctrlKey` → PINCH), keys (the engine first, then `shortcuts.ts`), focus and blur. It sizes the canvas with `ResizeObserver` (device-pixel-content-box when it is consistent), sets cursors (angle → CSS resize cursor; an SVG rotate cursor) and handles WebGL context loss.
- **`EngineStore` + `hooks.ts`** expose `useSelection`, `useTool`, `useUndoState`, `useHover`, `useCurrentPage`, `useCamera` and `useNode(store, id)` through `useSyncExternalStore`. Each snapshot is immutable per topic, and a node is re-read only after a change touches it.

## The wire encoding (interim) and the switch to kiwi

The payloads are JSON, but they use the schema's field names and meanings:
- Absent fields mean the absence value (§3.4).
- A CREATED change carries only the fields that differ from absence, plus `type` and `parentIndex`.
- `clearedFields` (kiwi field ids) is read on updates.
- Cleared fields are read as their defaults, and the engine's inverse writes the default value back rather than `clearedFields`, because the interim node model doesn't track absence separately.

Exactly two modules know the encoding: `engine/src/scene/CodecJson.{h,cpp}` and `src/renderer/src/engine/codec.ts`. When `engine/tools/schemagen` emits the kiwi codecs:
1. Replace those two modules with the generated codecs.
2. Swap the `Message`/`NodeChange` types in `codec.ts` for the generated ones.
3. Change the C++ `Field` bitmask to kiwi field ids. `kiwiFieldId()` and `fieldsOfKiwiId()` already map them.

The ABI does not change.

## Deviations from docs/engine.md (interim, on purpose)

**Scene and transactions**
- The node store is one struct per node with a field bitmask. §2.2's SoA `NodeTable` with facets, interned strings and opaque-field round-trip is not built yet. Coordinates are doubles in the engine and floats on the wire and GPU.
- Undo inverses are field values, not kiwi bytes.
- The spatial index is one AABB tree per page (§8.1). Culling still walks the tree.
- No render tree or tiles: the renderer draws directly from the scene.
- (Round 2) Groups now store their box, kept by layout (see the status section).
- Group opacity multiplies down instead of compositing a layer (E5).

**Graphics**
- `gfx::Device` is a subset of §6.1: buffers, pipelines over one built-in shader, and one pass on the default framebuffer. There are no textures, targets, MSAA or readback yet. Shaders are hand-written GLSL ES 3.00 (`gfx/gl/Shaders.h`); shadergen and naga come later.
- The WebGL context has `stencil: true`, because clip masks use the default framebuffer until the engine has its own targets. §6.1 asks for `stencil: false` once those exist.

**Bindings and build**
- The bindings, export list, key-code table and command ids are kept by hand. Vitest checks that the TS and C++ copies agree.
- Payloads are JSON, not kiwi (see above).
- Not yet in the ABI: `engine_layer_rows`, `engine_read_derived`, `engine_set_geometry`, `engine_find`, `engine_export`. Copy is `engine_encode_selection` (not §10.7's `engine_copy`).
- Tests are named `tests/unit/<area>.test.cpp`. There is no `wasm-node` preset: the vitest integration test runs the web build in Node with `document`/`window` stubs.

**Editing**
- Missing: double-click into layers, frame titles and overlay numbers (they need text), and snapping to guides and layout grids. The E2 decisions taken while building are in docs/engine.md §8.6.
